# ТЗ: маркетинговые отчёты — откуда пришёл клиент, по какой рекламе и почему ушёл

## 1. Зачем это нужно

Сейчас, чтобы понять, окупается ли реклама, нужно сводить данные вручную.
Цель — чтобы по любому периоду времени можно было одним взглядом на отчёты
ответить на три вопроса:

1. **Откуда пришёл клиент** — из какого мессенджера, по какой рекламной
   кампании, по какому объявлению или ключевой фразе.
2. **Что с ним происходило до заявки** — начал ли он разговор с ботом и на
   каком шаге передумал, если так и не оставил заявку.
3. **Почему сделка не закрылась** (или закрылась) — по какой причине клиент
   отказался, и какую сумму принесли те, кто всё-таки купил.

## 2. Путь клиента и три места, где он может «отвалиться»

Клиент проходит такой путь: **увидел рекламу → написал боту → бот довёл
его до заявки → заявка попала в CRM менеджеру → сделка закрылась (продажа
или отказ)**.

Потерять клиента можно на трёх разных этапах, и по каждому из них система
уже хранит свою причину:

- **Увидел рекламу, но не написал** — известно только общее число показов
  и переходов по рекламе, без привязки к конкретному человеку (это
  нормально: пока человек не написал боту, он анонимен).
- **Написал боту, но не дошёл до заявки** — известно, на каком именно шаге
  диалога он остановился и почему: отказался сам, не захотел давать
  телефон, ввёл его с ошибкой, не ответил вовремя или заблокировал бота.
- **Заявка дошла до менеджера, но сделка не закрылась** — известна причина
  отказа, которую менеджер указывает в карточке сделки при закрытии.

## 3. Что уже собирается и хранится

### Автоматически собираемые данные по обращениям

- При обращении система сохраняет, из какого мессенджера пришёл клиент
  (Telegram, MAX, WhatsApp) и через
  какую рекламную ссылку (источник, кампания, объявление, ключевая фраза —
  стандартная UTM-разметка рекламных ссылок);
- синхронизирует источник, указанный в самой CRM (например, «сайт», «звонок»,
  «мессенджер»);
- фиксирует, на каком шаге диалога с ботом клиент остановился, если не дошёл до
  заявки, и причину остановки;
- синхронизирует по сделкам суммы в работе и уже проданные;
- синхронизирует причину отказа, которую менеджер указывает при закрытии несостоявшейся
  сделки;

### Метрики и расходы рекламных кампаний

- После однократного подключения рекламного кабинета система автоматически
  загружает фактические траты, показы и клики по рекламным кампаниям в
  Яндекс.Директ и VK Рекламе.

### Обратная связь в рекламные кабинеты

- Отдельно от расходов и показов, система умеет отправлять результат обратно
  в рекламный кабинет: сразу после создания сделки в CRM бот передаёт в
  Яндекс.Метрику офлайн-конверсию «Запись на консультацию» по ClientID визита,
  без ручной выгрузки заявок. Это не отчёт, а канал обратной связи, который
  повышает качество автостратегий и оптимизации ставок в Яндекс.Директе.

### Ручные операции

- Расходы на каналы, которые не умеют отдавать статистику сами (например,
  офлайн-рекламу), пользователь вводит вручную по месяцам.
- Если клиент написал с двух разных мессенджеров, пользователь может вручную
  объединить обращения в одну карточку клиента, чтобы не считать его как
  двух разных людей.

Отчёты строятся по сохранённым данным и не «зависают» в ожидании ответа от
CRM или рекламного кабинета.

## 4. Какие отчёты уже есть

- **Конструктор отчёта** — свободный отчёт: выбираете любой разрез (реклама,
  источник, воронка, причина отказа, период) и любой показатель (число
  сделок, сумма, конверсия), результат можно выгрузить в файл.
- **Отчёт по рекламе (UTM)** — сравнение кампаний, объявлений и ключевых
  фраз по числу сделок и по сумме — видно, какая реклама реально приносит
  заявки и деньги, а какая нет.
- **Отчёт по источникам** — сравнение каналов CRM между собой.
- **Воронка сделок** — сколько заявок доходит до каждого этапа продажи и
  где теряется больше всего (этапы сделки в CRM).
- **Воронка бота** — путь пользователя внутри диалога с ботом: на каком
  шаге и по какой причине люди перестают отвечать, до того как заявка
  вообще попадёт в CRM; можно провалиться до списка конкретных людей.
  (Не путать с «Воронкой сделок» — это два разных этапа пути клиента,
  см. раздел 2.)
- **Реклама** — расход, показы, клики и активность кампаний в подключённых
  рекламных кабинетах.
- **Расходы и окупаемость** — сколько потрачено на источник или кампанию,
  сколько заявок и продаж это принесло, окупилась ли реклама.

## 5. Чего пока не хватает

Сейчас путь одного конкретного клиента приходится собирать из двух разных
мест: отдельно — где он остановился в диалоге с ботом, отдельно — чем
закончилась его сделка в CRM. Технически связать эти два куска между собой
можно (данные для этого уже есть), но единой карточки «вот один клиент, и
вот вся его история от рекламы до результата» пока нет.

**Что нужно добавить:** отчёт-карточка по конкретному клиенту, где в одном
месте видно: с какой рекламы он пришёл → что происходило в диалоге с ботом
(в том числе если он ушёл, не дойдя до заявки) → что случилось с его
сделкой (продажа с суммой или отказ с причиной). Данные для склейки уже
существуют по отдельности — по обращению в боте, по объединению дублей
одного клиента из разных мессенджеров и по сделке в CRM; не хватает только
отчёта, который сводит их в одну карточку.

**Ещё не хватает:** приоритета автоматического расхода над ручным в отчёте
«Расходы и окупаемость» — см. раздел 6, пункт про подключённый рекламный
кабинет.

## 6. На что обратить внимание при оценке качества данных

- Если клиент перешёл по ссылке без рекламной метки (например, написал
  боту напрямую по ссылке из шапки профиля), у него не будет данных о
  рекламе — отчёты должны честно показывать долю таких обращений, а не
  скрывать их.
- Причину отказа по сделке менеджер указывает вручную — отчёты должны
  отдельно показывать, сколько отказов осталось без указанной причины,
  чтобы было видно, насколько аккуратно ведётся CRM.
- Когда рекламный кабинет подключён и отдаёт расход автоматически, отчёт
  об окупаемости должен использовать этот расход как приоритетный. Ручной
  расход должен использоваться только для месяцев и кампаний, по которым
  автоматический расход отсутствует; источники не должны суммироваться. После
  подключения рекламного кабинета ранее введённое ручное значение должно
  сохраняться в истории, но не участвовать в расчёте при наличии
  автоматического расхода. **Сейчас это не так:** отчёт «Расходы и
  окупаемость» учитывает только ручные расходы и никак не связан с
  автоматическим расходом из подключённых кабинетов — это открытая задача.

## 7. Критерии приёмки

- По любому периоду можно получить: сравнение рекламных кампаний по числу
  заявок и сумме продаж; список причин, по которым клиенты отказываются
  (сколько раз каждая встречалась); путь по шагам диалога с ботом с
  причинами, по которым люди не доходят до заявки; окупаемость рекламы там,
  где заведены расходы. Для периода, начинающегося или заканчивающегося
  внутри месяца, в расчёт должна включаться доля месячного расхода,
  пропорциональная числу дней этого периода в соответствующем месяце —
  **сейчас не реализовано**: расход месяца учитывается целиком, если период
  просто пересекает этот месяц, без деления по дням.
- По конкретному клиенту можно проследить всю цепочку: с какой рекламы
  пришёл → как вёл себя в диалоге с ботом (в том числе если ушёл, не оставив
  заявку) → чем закончилась сделка и почему.
- Все цифры в отчётах воспроизводимы и не требуют ручного сведения данных
  из разных источников.
